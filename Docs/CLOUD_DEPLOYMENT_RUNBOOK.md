# Облачный запуск VSM Conductor Trainer

## Архитектура MVP

Одна Linux VM в Yandex Compute Cloud запускает три контейнера из корневого `compose.yaml` и cloud-overlay:

- `database`: PostgreSQL 16, данные в Docker named volume `vsm_database`.
- `backend`: ASGI API v2, доступен только внутри Docker-сети и на loopback VM (`127.0.0.1:18767`).
- `caddy`: публичный HTTPS-вход, автоматические сертификаты и прокси к `backend:18767`.

PostgreSQL не публикует порт 5432. Публичные входящие порты — только TCP 80/443. Порт 18767 не открывается в облачном firewall. SSH 22 открывать только с доверенного адреса `/32`. API-ключ Yandex хранится в `Backend/.env`, пароль БД — в корневом `.env`; секреты не попадают в Git или Unreal.

Это дешёвый односерверный вариант: при сбое VM одновременно недоступны backend и БД. Для пилота понадобится отдельное проверенное резервное копирование.

## Стоимость и грант

В форме создания VM для конфигурации 2 vCPU с долей 50%, 2 ГБ RAM, 13 ГБ HDD и динамическим публичным IPv4 была показана оценка **1 789,86 ₽/месяц**. Это расчёт на работу 720 часов, без исходящего трафика и запросов к ИИ; итог зависит от потребления.

В биллинге видны грант 4 000 ₽ и даты 27.09.2026–26.11.2026. Владелец проекта сообщил, что для планирования нужно считать грант доступным только на месяц. При консервативном месячном расчёте VM займёт около 1 789,86 ₽, оставив примерно 2 210,14 ₽ на трафик и ИИ. Если грант фактически доступен весь отображённый срок в 60 дней, две месячные оценки VM составят около 3 579,72 ₽ и оставят около 420,28 ₽. Проверить срок действия и остаток непосредственно в биллинге до следующих расходов; после окончания гранта работающая VM может тарифицироваться платному аккаунту.

Остановленная VM не тарифицирует вычислительные ресурсы, но хранение диска и публичного IP может продолжать тарифицироваться. Перед удалением выгрузи и проверь резервную копию; не удаляй Docker volume с нужными данными.

## Следующие шаги

1. Дождаться статуса `Running` и записать внешний IPv4 VM в консоли Compute Cloud.
2. После получения текущего внешнего IPv4 владельца добавить в `vsm-conductor-public` правило TCP 22 с источником `<IPv4>/32`. До этого удалённый SSH-доступ остаётся закрытым.
3. Для HTTPS указать собственный домен через A-запись на публичный IPv4. Для временного MVP можно использовать имя `<IP-с-дефисами>.sslip.io`, например `203-0-113-10.sslip.io`; это сторонний DNS-сервис без SLA. HTTPS-сертификат Caddy требует DNS, указывающий на VM, и открытых TCP 80/443.
4. По SSH установить Docker Engine и Compose plugin из официального репозитория Docker для Ubuntu 24.04.
5. Разместить в `/opt/vsm-conductor-trainer` backend, `Contracts`, корневой `compose.yaml`, `deploy/cloud/compose.yaml` и `deploy/cloud/Caddyfile`. Git push не требуется.
6. Только после отдельного подтверждения владельца передать root `.env` в `/opt/vsm-conductor-trainer/.env`, а backend `.env` — в `/opt/vsm-conductor-trainer/Backend/.env`; на Linux выставить `chmod 600` обоим файлам.
7. Из каталога `/opt/vsm-conductor-trainer` задать имя API и запустить:

       export VSM_API_DOMAIN='api.example.com'
       docker compose --env-file .env -f compose.yaml -f deploy/cloud/compose.yaml config --quiet
       docker compose --env-file .env -f compose.yaml -f deploy/cloud/compose.yaml up -d --build

   Для временного DNS замени `api.example.com` на имя, указывающее на IPv4 VM. Caddy получает и обновляет TLS-сертификат автоматически.
8. Проверить `docker compose ... ps`, затем `curl -fsS https://<имя-API>/health`; если маршрут health-check менялся, сверить актуальный контракт в `Docs/BACKEND_API.md`. Проверить вход/регистрацию и тестовый сценарий без реального запроса к YandexGPT. Реальный вызов модели расходует квоту.
9. После HTTPS-проверки записать домен и задать в `Config/DefaultGame.ini` `ApiBaseUrlV2 = https://<имя-API>` без `/v1`, `/v2` и завершающего `/`.

## Резервная копия PostgreSQL

Создай логический дамп внутри каталога проекта, не включая секреты:

       mkdir -p backups
       docker compose --env-file .env -f compose.yaml -f deploy/cloud/compose.yaml exec -T database pg_dump -U vsm -d vsm | gzip > "backups/vsm-$(date -u +%Y%m%dT%H%M%SZ).sql.gz"

Дамп нужно скопировать с VM в отдельное надёжное хранилище и периодически проверять восстановление. Дамп на том же диске не защищает от потери VM/диска. Не загружать его в публичный репозиторий.

## Проверка конфигурации

Compose overlay проверен локально командой `docker compose config --quiet` с примером/тестовым окружением. Контейнеры локально не запускались, Docker daemon недоступен; облачные контейнеры ещё не запускались. Изменения API-контракта не входят в cloud overlay.
